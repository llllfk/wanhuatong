给客户看的搭建说明

这个万花筒是怎么搭起来的

用大白话讲清楚：它不是 App，是一个网页；怎么做出来的、怎么放到网上、客户怎么打开就能用。

一句话先说清

我们做的是一个网页程序。大人把链接发给客户，客户用 iPad 自带的浏览器（Safari）打开，点一下允许摄像头，就能玩。

不上架苹果应用商店，也不用装什么编程积木软件。换一批孩子、换一台 iPad，只要打开同一个链接就行。

整体是怎么搭的

1
先做出网页 先做成一个可在手机 / 平板浏览器里打开的网页，把万花筒画面、上传照片、选动作、开摄像头这些功能都写好。
2
再放到网上 开发完成后，把网页发布上线。上线之后会得到一个可以打开的网址（链接）。
3
最后发给客户用 把这个链接发给老师 / 机构。他们在 iPad 上打开就能用，不用再装 App。

注意：做好代码不会自动上网。只有明确「发布 / 上线」之后，客户才能用正式链接打开。

客户那边怎么运行起来

  1. 收到我们发的网页链接。
  2. 用 iPad 的 Safari 打开（建议横着拿）。
  3. 第一次会问「要不要用摄像头」，点允许。
  4. 先上传几张照片、选好动作规则，再点「运行」开始表演。

想更像 App：在 Safari 里用「添加到主屏幕」，以后桌面点一下图标就能进。

为什么必须用「安全链接」

要用摄像头，浏览器规定必须是带锁的安全网址（地址一般以 https 开头）。我们上线后的正式链接就是这种。

如果用普通不安全的地址，或者在预览小窗口里试，摄像头有时开不了——以发布后的正式链接、在真机 iPad 上打开为准。

画面识别跑在哪里

孩子对着摄像头做动作时，识别是在这台 iPad 自己里面完成的。摄像头画面不会传到我们服务器，也不会拿去存档。

上传的照片也只是这一次打开网页时用，关掉页面、换人再开，上一组的图不会还挂在上面。

代码大概长什么样（大白话）

整个项目就是一堆网页文件。打开电脑上的项目文件夹，最要紧的几块可以这么理解：

  • 设计页 孩子上传照片、选「用手势」还是「用身体」、给四种效果绑动作的地方。
  • 运行页 点「运行」之后：开摄像头、认动作、驱动万花筒画面转起来。
  • 万花筒画面 负责把照片折成一圈圈对称花纹；旋转、放大、缩小都在这里画出来。
  • 认手 / 认姿势 看摄像头里的手或身体，判断现在是握拳、举手还是叉腰等。
  • 规则配置 记下「哪个动作管放大、哪个管换图」；动作规则会记在这台 iPad 自己的浏览器里。

程序跑起来时，大致就是这么一条线（不用记名词，看流程就行）： 

打开网页
  → 设计页：上传照片 + 选动作规则
  → 点「运行」
  → 打开摄像头
  → 本机认出手势 / 身体姿势
  → 按规则：转 / 放大 / 缩小 / 换图
  → 画到万花筒画面上

以后如果要加一个新姿势，主要是改「认姿势」那一块，再在设计页里多给一个可选按钮；改完重新发布，客户刷新就能用。

代码放在我们这边的项目仓库里维护。客户平时不用碰代码，只要打开链接就行。

以后要改功能怎么办

  1. 在项目里改好内容（比如加姿势、改默认规则）。
  2. 改完后再发布一次。
  3. 客户刷新网页（或重新打开链接）就能用到新版本。

平时几个客户共用同一个链接就够了。如果以后要绑自己的域名，也可以再加，但不影响现在先用正式链接开玩。

和「装 App / 用积木课」有什么不一样

  • 不是苹果商店里的 App，不用审核上架、不用更新商店版本。
  • 不是 Scratch 那种积木课，孩子不用搭积木，打开网页就能玩。
  • 维护简单：我们改网页 → 发布 → 客户打开链接就是最新版。
